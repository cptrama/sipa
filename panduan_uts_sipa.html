1 Ringkasan Eksekutif (Elevator Pitch 1-2 Menit)

Gunakan kalimat ini saat dosen penguji meminta: "Coba jelaskan secara singkat aplikasi apa yang kamu bangun dan apa hubungannya dengan mata kuliah Komputasi Awan?"

"Selamat pagi/siang Bapak/Ibu dosen penguji. Projek UTS saya adalah SIPA (Sistem Informasi Pengumpulan Tugas), yaitu aplikasi web berbasis kontainer (containerized application) yang berfungsi memfasilitasi distribusi materi perkuliahan, pembuatan tugas kuliah, dan pengumpulan tugas oleh mahasiswa secara real-time, terstruktur, dan aman.

Korelasinya dengan mata kuliah Komputasi Awan, projek ini dirancang dengan pendekatan Cloud-Native. Sistem dikemas menggunakan Docker Container sehingga memenuhi prinsip 'Build Once, Run Anywhere', siap dideploy pada model layanan Platform-as-a-Service (PaaS/Render) dengan mekanisme dynamic port binding, serta mengadopsi prinsip The Twelve-Factor App untuk efisiensi resource server awan."

2 Korelasi Nyata dengan Mata Kuliah Komputasi Awan

Dosen ingin menguji apakah Anda memahami konsep komputasi awan di balik aplikasi, bukan sekadar logika pemrogramannya. Berikut 4 pilar komputasi awan yang diterapkan pada SIPA:

Prinsip Komputasi Awan Implementasi Teknis pada SIPA Manfaat Arsitektural di Cloud
1. Kontainerisasi (Docker) Menggunakan Dockerfile berbasis php:8.2-apache yang mengompilasi library ekstensi (zip, pdo_sqlite, opcache, mod_rewrite). Menghilangkan ketergantungan OS fisik. Menjamin aplikasi berjalan identik di komputer lokal maupun server awan (consistency & zero environmental drift).
2. Cloud Model: PaaS & CaaS Skrip docker/entrypoint.sh mendeteksi environment variable $PORT dinamis (misal di Render/Cloud Run) lalu mengonfigurasi Apache otomatis. Mendukung Dynamic Port Binding. Tidak membutuhkan instalasi server fisik manual (IaaS), melainkan dikelola langsung oleh orkestrasi PaaS.
3. Resource Optimization Menggunakan micro-framework Flight PHP dan SQLite WAL Mode, bukan framework monolitik yang boros RAM. Aplikasi hanya memakan < 50 MB RAM dan boot dalam hitungan milidetik. Sangat efisien untuk cloud instance tier ekonomis / serverless.
4. Storage Segregation Pemisahan berkas unggahan ke storage/uploads dan berkas basis data ke database/app.db di luar webroot. Siap dipetakan ke Cloud Persistent Volume atau migrasi ke Cloud Object Storage (AWS S3/Google Cloud Storage) tanpa merombak logika kode.

3 Spesifikasi Arsitektur & Teknologi

Komponen Perangkat Lunak

  • Runtime: PHP 8.2 (Opcache enabled)
  • Web Server: Apache 2.4 (VirtualHost, mod_rewrite)
  • Micro-Framework: Flight PHP (v3.19+)
  • Database Engine: SQLite 3 via PDO (Foreign Keys ON, Journal WAL)
  • Frontend: Tabler Core UI (Bootstrap 5 based) + Tabler Icons & Bootstrap Icons
  • Version Control: Git & GitHub Repository

Fitur Arsitektural Kunci

  • Front Controller: Seluruh traffic diatur via public/index.php.
  • Role-Based Access Control (RBAC): Middleware ketat memisahkan hak akses Dosen vs Mahasiswa.
  • Clean Routing & Groups: Pemisahan route grup /dosen dan mahasiswa.
  • Native Session Security: Enkapsulasi session aman dengan regenerasi token.

4 Fitur Utama Berdasarkan Peran (Role)

Role Dosen Pengampu

  • Dashboard Realtime: Menampilkan statistik total pertemuan, tugas aktif, dan rasio pengumpulan tugas mahasiswa.
  • Manajemen Pertemuan: Menambah, mengubah jadwal, dan mengunggah berkas materi ajar perkuliahan (PDF/PPT/DOCX).
  • Manajemen Tugas: Menetapkan judul, petunjuk, serta waktu buka & tutup (deadline) otomatis.
  • Pemeriksaan & Penilaian: Input nilai angka, feedback tertulis, dan opsi Buka Kembali pengumpulan.
  • Download Massal (Bulk ZIP): Mengunduh seluruh tugas mahasiswa dalam 1 file ZIP terkompresi rapi.
  • Rekap Nilai & Export CSV: Menghasilkan rekapitulasi nilai satu semester yang bisa diunduh ke Excel/CSV.
  • Manajemen Mahasiswa: Tambah mahasiswa baru, edit kelas, dan tombol Reset Password jika lupa sandi.

Role Mahasiswa

  • Timeline Perkuliahan: Mengetahui daftar pertemuan, topik materi, dan berkas ajar yang bisa langsung diunduh.
  • Status Tugas Realtime: Indikator status otomatis: Terbuka, Belum Dibuka, atau Sudah Dinilai.
  • Pengumpulan Berkas: Mengunggah berkas tugas sebelum deadline dengan validasi ekstensi dan batas ukuran file (20 MB).
  • Transparansi Nilai: Mahasiswa dapat melihat nilai dan catatan/feedback koreksi langsung dari dosen.
  • Keamanan Akun: Mekanisme wajib ganti password awal saat login pertama kali, serta pengaturan foto profil (avatar).

5 Aspek Keamanan & Ketahanan (Standar OWASP)

  • Pencegahan SQL Injection: 100% interaksi database menggunakan PDO Prepared Statements dengan parameter binding.
  • Pencegahan XSS (Cross-Site Scripting): Menggunakan fungsi helper e() yang memanggil htmlspecialchars(..., ENT_QUOTES, 'UTF-8') pada seluruh variabel tampilan.
  • Proteksi CSRF (Cross-Site Request Forgery): Setiap form POST diverifikasi dengan token CSRF unik menggunakan hash_equals().
  • Penyimpanan Berkas Aman: Berkas tugas disimpan di luar folder publik (storage/uploads/). File tidak dapat dieksekusi langsung via browser URL untuk mencegah serangan Web Shell RCE. Unduhan disalurkan aman melalui controller.
  • Validasi Konten Berkas (Magic MIME): Validasi memeriksa header biner berkas menggunakan PHP finfo.
  • Anti Brute-Force Rate Limiting: Membatasi login maksimal 5 kegagalan per 15 menit per NIM/IP. Dilengkapi pencatatan insiden ke Security Audit Log.

6 Simulasi Tanya-Jawab Kritis Dosen (Q&A)

Q1: "Di mana letak konsep Komputasi Awan pada sistem ini? Kenapa tidak disebut web biasa saja?"
Jawaban Anda:
"Korelasinya terletak pada arsitektur pengemasan dan kesiapannya di ekosistem cloud (Cloud-Native Deployment), Pak/Bu. Aplikasi ini dikemas secara utuh ke dalam Docker Container. Di dalamnya terdapat konfigurasi dynamic port binding di entrypoint.sh untuk cloud PaaS seperti Render, serta pemisahan state storage yang memudahkan integrasi dengan cloud persistent volume. Kami juga menerapkan filosofi The Twelve-Factor App untuk efisiensi komputasi awan."
Q2: "Mengapa kamu menggunakan Docker? Apa bedanya dengan menyewa hosting biasa?"
Jawaban Anda:
"Dengan Docker, kami mencapai konsistensi lingkungan (environment parity). Pada web hosting biasa, kita terikat konfigurasi PHP dan modul server penyedia. Dengan Docker, kita mendefinisikan infrastruktur sendiri lewat kode (Infrastructure-as-Code): versi OS, PHP 8.2, modul Apache, hingga konfigurasi permission folder. Aplikasi dipastikan berjalan 100% sama baik di laptop pengembang maupun di kluster server cloud."
Q3: "Mengapa memilih Flight PHP dan SQLite, bukannya Laravel dan MySQL?"
Jawaban Anda:
"Pertimbangannya adalah Cloud Resource Optimization (Efisiensi Sumber Daya Awan). Framework besar seperti Laravel beserta server MySQL terpisah membutuhkan RAM minimal 1-2 GB di cloud instance. Sementara kombinasi Flight PHP dan SQLite ber-mode WAL (Write-Ahead Logging) hanya membutuhkan memori di bawah 50 MB dengan latency milidetik. Ini sangat ideal untuk deployment cloud skala micro/tier hemat biaya tanpa mengorbankan integritas data."
Q4: "Bagaimana jika suatu saat mahasiswa bertambah jadi ribuan? Bagaimana strategi skalabilitasnya (Scalability)?"
Jawaban Anda:
"Arsitektur SIPA didesain modular untuk Horizontal Scaling di Cloud:
1. Database: Abstraksi query PDO memudahkan migrasi database ke Managed Cloud Database seperti Amazon RDS (PostgreSQL/MySQL) tanpa mengubah logika controller.
2. Storage: Folder penyimpanan storage/uploads tinggal dialihkan ke Cloud Object Storage (Amazon S3 / Google Cloud Storage).
3. Container: Image Docker yang sudah ada tinggal di-deploy pada Kubernetes atau auto-scaling group yang otomatis menambah jumlah kontainer saat beban kerja melonjak."
Q5: "Bagaimana kamu memastikan berkas tugas yang diunggah mahasiswa aman dari hacker (misal upload virus/script jahat)?"
Jawaban Anda:
"Kami menerapkan Defense-in-Depth (Keamanan Berlapis):
1. MIME Sniffing Prevention: Kami memverifikasi tipe biner file menggunakan PHP finfo, bukan sekadar melihat ekstensi nama berkas.
2. Penyimpanan Luar Webroot: File disimpan di storage/uploads/, sehingga tidak dapat dieksekusi secara langsung via browser.
3. Obfuscated Filename: Nama file diganti dengan hash acak unik di server untuk mencegah serangan Path Traversal."
Q6: "Bagaimana cara kerja status tugas otomatis (Terbuka, Belum Dibuka, Ditutup)?"
Jawaban Anda:
"Status tugas dihitung secara dinamis dan real-time pada saat runtime menggunakan perbandingan Unix Timestamp waktu server (WITA - Asia/Makassar). Jika waktu sekarang kurang dari dibuka_pada, statusnya 'Belum Dibuka'. Jika berada di antara batas buka dan ditutup_pada, statusnya 'Terbuka'. Jika melewati batas tutup, otomatis berubah menjadi 'Ditutup' dan form pengumpulan langsung dikunci oleh sistem."

7 Panduan & Alur Live Demo di Depan Penguji

  1. Tunjukkan Sisi Cloud/Docker: Buka terminal atau Docker, perlihatkan container SIPA aktif berjalan. Jelaskan baris dependensi pada Dockerfile.
  2. Skenario Dosen (Membuat Tugas): Login sebagai dosen, buat pertemuan baru, unggah materi kuliah, lalu buat 1 tugas baru dengan deadline.
  3. Skenario Mahasiswa (Mengumpulkan Tugas): Buka jendela Incognito, login sebagai mahasiswa. Tunjukkan materi bisa diunduh, lalu lakukan unggah berkas tugas.
  4. Skenario Penilaian & Export: Kembali ke akun dosen, perlihatkan tugas mahasiswa langsung terdata. Berikan nilai dan feedback. Tunjukkan fitur Download ZIP dan Export Rekap Nilai ke CSV.
